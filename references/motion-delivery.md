# 20 秒样片与完整 HTML

## 把所选风格用于用户选题的连续动画

- 从用户选定风格的原始示例图片、视频和源码提炼出一套配色、文字层级、物体画法、质感和构图规则；沿用它实现可独立控制的主体与信息元素。
- 以源码中的实际时序为参考设计事件：起始状态 → 可观察变化 → 理解结果 → 转入下一信息。静止停留用于阅读，不用无意义抖动填满时间。
- 机制解释的运动优先于装饰。通过移动、增减、分组、连接、遮挡、变形或镜头运动揭示关系。不要把原始参考图当背景后只加字幕或缩放。
- 前后逻辑连续时保留相关物体并让它演变；确需换场时采用该风格的转场。避免每句话都翻一页，也不强求所有内容一镜到底。
- 20 秒样片应有实质解释、至少一段连续变化及一次有意义的衔接，足以检验文字阅读速度与声音同步。不要只交片头标题。

## 实现约定

优先适配参考的 Canvas/JS 方法；需要时可采用更适合内容的实现，但保留获选风格。创建真实可播放 HTML，包含播放/暂停、拖动进度、当前时间、重播，有声音则有声音开关。

以时间 t 驱动画面，允许 seek 到任意时刻并得到稳定结果。用有种子的随机数，不让刷新、暂停或拖动改变角色和纹理。暴露清晰的渲染/时间接口便于本地验收和之后按需导出；例如 window.seek(t)、window.DURATION。测试浏览器交互时仍遵循当前浏览器工具规则，不通过受限的 evaluate 执行状态修改。

中文显示依赖需可靠。画面内文字简明：标题、关键数字和标签分别建立层级，避免说明文字堆叠；以手机观看也能阅读为准。默认 16:9，但用户指定画幅优先。

当前用户提供 BGM 时使用该 BGM，复制到成品依赖内并按实际音乐设计节奏；不硬编码旧任务的音乐路径。未指定时参考所选风格声音库安排适当音效，可无旁白，不擅自调用付费 TTS。原归档的 no voiceover 是提示词选项，不禁止用户要求旁白。样片应体现计划采用的声音方案，不能承诺已验证没有实际听过的听感。

声音从用户播放操作启动；暂停、拖动、重播时停止旧事件并从新时间对齐，不允许叠播。原生循环/重播处理须验证。需要联网资源时说明，优先使用本地必要依赖，不把原站在线服务当成成品必需条件。

## 验收

样片和全片都需要：

1. 用实际 HTTP 服务提供页面，先验证端口可访问，再在 Codex 内置浏览器打开。需要给用户看时创建/接管可见标签页，确认目标页面确实显示，并 markDeliverable 保留。
2. 操作播放、暂停、拖动与重播，核对时间推进、声音重启和画面状态；检查页面错误、字体/图片/音频缺失。
3. 覆盖整个时间轴；全片按段检查，不能以只看开头代表看完。用时间戳记录明显问题，重点加密检查转场和机制变化。
4. 查看实际帧与连续过程：文字是否足时可读，重要物体是否被遮挡，视线路径是否清楚，动作和声音是否匹配，过渡是否表达正确因果。单张截图和高帧率都不能独自证明动效质量。
5. 对照用户选定风格的原始图片、参考视频和源码：保留质感、文字层级、空间关系和运动语言；发现明显退化先修正。静态图仅证明视觉方向，动态样片才验证时间设计。
6. 按脚本复核事实、因果、例子的限制和结论；比如“更少假设”不能被画成“更短文字就一定更正确”。

样片约 18–22 秒，验收后等待第二次确认。完整版本延续已经获批的实现，覆盖全部内容并再次验证，不新增与任务无关的审核流程或自动多 Agent 循环。

## 交付

样片交 `sample/index.html`，完整版本交 `final/index.html` 和必要相对路径依赖。提供可见播放入口与本地绝对路径，不只贴代码、只给截图或只列验证报告。视频内容占主要画面，不加无关产品面板和开发术语。

结尾简短陈述已交付版本、时长、已验证项目和实际限制。用户未要求时不生成 MP4、不发布到外部平台、不宣称全面优于参考。
