# 三张示例图与原生选择弹窗

## 展示内容

从全部 86 种中推荐三个，每个直接使用归档的 `poster.jpg`。先实际查看图片，核对候选 ID、名称与元数据，不能仅靠文件名猜测。中文名由 `gallery-zh.json` 的 names 数组按 ID 减一索引取得，英文原名由 style-index.json 取得。

在回复中顺序展示 A、B、C，每个包含：中英文名称、一句与用户选题相关的理由、一张原始示例图片。图片用 Markdown `![方案名称](绝对图片路径)`，不要用 HTML 页面、附件文件列表、仅工具截图或三段视频替代。原图无需重生成、拼贴或改写文字。说明“以下是原始风格示例，选定后会制作你的选题样片”，不要声称图片是为用户选题制作的。

不调用 ImageGen，不生成九张关键帧，不制作三段 5 秒样片。极简内容思路可以先用一句话说明；详细样片脚本放在选择之后。

## 原生弹窗

先在用户可见回复中展示三图，再调用 Codex 的问题选择工具。

优先使用 `functions.request_user_input_async`：一个自包含问题、三个真实风格选项。最推荐的方案排第一并标注推荐；A/B/C、名称、图片和工具选项必须一致。示意参数结构如下，实际调用时替换为选出的名称：

```json
{
  "questions": [{
    "title": "这次视频你想采用哪一种风格？选定后我会制作约20秒样片。",
    "options": [
      "A · 实际中文名 / Actual name（推荐）",
      "B · 实际中文名 / Actual name",
      "C · 实际中文名 / Actual name"
    ]
  }]
}
```

该工具立即返回，用户回答稍后到达。发出后不要继续依赖选择的制作，不用睡眠轮询；可结束本轮等待用户。若在等待期间已收到有效选择，直接继续样片。若需要最终回复结束本轮，最终回复仍应完整呈现三个方案及图片，不能要求用户翻找已折叠的进度消息。

仅在 Plan 模式且 `functions.request_user_input` 可用时，才可以使用同步原生选择工具；不要在 Default 模式调用它，不为弹窗而修改模式。原生工具确实不可用时明确说明，退回文字选择。不要用浏览器 JS 弹窗、Windows 通知或 codex-notifications 替代。

工具中的默认预选不是确认。用户明确选择 A/B/C、名称或 ID 都可接受。用户选择图库中另一种风格时直接匹配，不强制局限在推荐三种。用户只是提问或要求换推荐则先回应，不猜其最终选择。用户事先明确指定风格时，不重复弹窗。

## 回复结尾保留更多风格入口

保留内置双语、三列、点击主图播放案例的 86 风格图库。使用已核验可访问的本次图库链接，或用 `scripts/gallery.py --output <本次新目录>` 导出 HTML、86 封面和 172 个视频后提供可点击地址。不要使用失效端口或仅原站链接。

首次推荐回复的末尾写：“还想看看其他风格？[浏览全部86种风格](实际可用地址)，复制喜欢的风格名称发给我即可。”它是可选补充，三种推荐必须在回复内直接显示，不另建 `design-options.html`。

## 选择后

把工具回答或用户明确文字选择及对应 style ID 记录下来，按主流程深入研究所选风格并制作约 20 秒的用户选题 HTML 样片。不要在此处新增图片生成或第二次风格选择。样片通过后才能扩展全片。
