# 口播类 / Talking Head

适用于用户已有真人或虚拟形象口播，希望保留原声、精剪重复表达，并用素材和连续动画辅助讲述。用户明确说“口播类”即已选风格，不重新三选一；仍先交约 20 秒样片，认可后扩展全片。

- `assets/custom/talking-head/explainer.mp4`：150 秒完整成片的 720p/60fps 浏览副本；原母版为 1920×1080/60fps，保留在原项目。浏览副本不用于高清导出。

- `source/index.html`：完整可编辑 HTML 案例与本地依赖。通过本地 HTTP 服务浏览；并非只有视频播放器外壳。
- `editing/original-edit-plan.json`：原剪辑决策证据，包含重说、废弃起句的删除理由；旧 source/output 路径仅为归档记录，不执行。原始未剪 MOV 不随包附送。`original.srt` 与 `edited.srt` 可对照理解删剪和字幕修订，不能把旧剪点应用到新素材。
- `manifest.json`：收录文件哈希；来源说明在 `source/assets/sources.txt` 及子案例的 credits 文件。

## 新口播的制作方法

1. 先看实际视频并读取字幕。区分完整观点、重说、卡壳、录制自语和有用停顿。删除废弃表达时保留完整正确的一遍、呼吸和尾音；只有字幕时不假装已经听过音频。编辑时间线须保留源时间到成片时间映射。
2. 保留用户观点、原声与论述顺序；字幕纠错、语义断句与口播同步。原例阈值 `maxGap=0.3` 只是该节目的设置，不能把所有句间停顿统一压到同一长度。
3. 为每一段确定“观众此刻需要看见什么”：说观点看人物；讲证据看真实截图/资料；讲步骤看操作；讲机制看过程动画。不让动画只是装饰性地漂浮，也不让人物一直占据相同面积。
4. 原例视觉为米白桌面、薄玻璃边缘、圆角素材框、深色粗圆标题和左下人物窗。1920×1080 中原例小窗为 x=48、y=667、w=310、h=365。它是参考构图，不是其他画幅的硬编码标准；按人脸、手势与字幕实际位置调整安全区。虚拟形象是原素材内容，不是必须给真人换脸的要求。
5. 真实资料能用就用；保留正确比例和可读字号。已有案例先导出适当清晰度的视频再嵌入，较重场景用预渲染或合并视频纹理；不为了“全部实时”让主画面卡顿。示意界面不得声称为真实录屏，概念数字不得冒充真实平台数据。
6. 所有动作依赖同一口播时钟。物件先进入、展开或变形，再强调结果，最后有因果地让出空间。任意拖动都应复现正确画面，暂停同步停声，播放到结尾不闪回。
7. 音效只跟随关键动作/落点，不给每个字或每张小卡片配重复声。BGM让位于原声；本例的人声+3dB、音乐再降10dB是该素材的反馈结果，不是通用增益。保留用户当次指定BGM并测量实际峰值；技术电平检查不等于主观听感验收。
8. 先从新口播挑约20秒连续内容，覆盖人物切换、至少一个解释动作及一处转场，展示可播放HTML；确认后扩展全片。用户未提供口播素材时先推进脚本/素材规划，明确需要原视频才能验证精剪和口型同步，不能拿参考人物/声音冒充新作品。

## 复用边界与验收

迁移运动函数、排版关系、媒体同步、字幕和动作音效方法；替换本期事实、日期、模型名称、仓库地址、体积数字、图片、人物与声音。六个内嵌作品是本期叙事素材，不要求新片都携带它们。原有系统字体等素材保持原署名；需要跨平台再分发时按各素材条款选择字体与替代品，不把整包统一声明为自有授权。

检查普通讲述、人物扩缩、密集材料、结尾四类场景的连续时间序列；实际播放检查文字可读、资料不遮脸、字幕不挡要点、音画对应和动效帧率。测试暂停/拖动/重播/末帧；从搬移后的目录验证本地依赖。没有完整音频回听时明确保留这一边界。
