# #88 · Vibe 知识讲解 / Vibe Knowledge Film

仅在用户选定 #88、Vibe 知识讲解、夜曲或寓言时加载本指南及专属引擎。它是一项带导演方法和代码工具的风格，不是全局制作规范。不得把它的字幕、配色、无旁白偏好或 Canvas 引擎套到其他风格。

## 选择一个世界

- **C 夜曲 / Nocturne**：抽象概念、物理、生物、数学、不可见机制。深蓝黑空间，克制的金/冰蓝/玫红，宋体、细线仪器；解释主体是可辨认的实物或装置，光点与辉光只辅助。作者示例：`assets/custom/vibe-knowledge-film/examples/fold_C/`。
- **B 寓言 / Fable**：行为、心理、动物实验与生活故事。温暖的扁平插画，前中后景视差、可辨认角色和连续行动，用贯穿的计时器、读数或其他道具揭示因果。作者示例：`assets/custom/vibe-knowledge-film/examples/pigeon_B/`。

根据选题自行选 C/B 并简短说明，不增加强制确认。用户指定时直接采用。图库是一个条目、两段具名示例；不要把两个世界误当两个新的独立 style。

## 保持本 Skill 的流程

三图推荐与选择 → **约20秒 HTML 样片** → 用户确认 → 完整 HTML。用户已指定本风格则直接做样片。上游约30秒样片、额外文案/分镜确认等流程不引入。示例约33秒是作者参考，不能拿它代替用户样片。

默认中文、16:9，以可读字幕、机制动画、音乐/动作音效讲述；这只是 #88 的起点，旁白、画幅、语言、时长和用户指定 BGM 均以当次要求为准。无旁白不是禁令。保留全局两个确认点，未通过样片不做长片。

## 导演与解释方法

1. 核实事实、数字、实验条件与因果边界。区分真实机制、示意缩放和视觉比喻。每条片先写观众最终应理解的一件事。
2. 按“熟悉的现象 → 反常结果 → 可观察的机制 → 回到最初问题”组织极简脚本；不要求所有题材机械套四段。字幕和分镜一起写，每个节点注明：时间、观众读什么、看哪个对象、对象做什么、由此能推断什么。
3. 把抽象名词落成可辨认对象，把解释动词落成动作：输入、碰撞、累积、阻塞、筛选、反馈。结论必须能从刚发生的过程看出来；仅贴标签、出现大字或连线不算解释。
4. 同一对象的颜色、形状、尺度参照与身份持续一致。以运动、跟随镜头、遮挡或变形衔接前后场景，避免靠黑屏和换页掩盖关系。明确空间/时间跳跃时可使用有理由的剪切；不能为了无缝而混淆因果。
5. 先实现最难、最能检验机制的一镜。样片取连续的小过程，包含铺垫、变化、结果和可读停留；不拿20秒全部做片头，不把整片塞进20秒。
6. 文字服从画面时间：先让观众识别对象，再发生关键动作，再落结论。字幕保留底部约80%–95%的安全区，测量最长句的宽度。C 可加英文辅字幕；B 可用逐字强调。用户只要中文时不加英文；不要为凑行宽删除逻辑限定语。

## 研究材料与运动

先查看本模块 poster 与两段 `nocturne.mp4`、`fable.mp4`；它们由作者公开 GIF 转码，800×450、10fps、**无音轨**，仅供快速浏览，不作为高帧率运动或声音质量证据。选定世界后打开对应的可运行 HTML 源码示例，研究完整时间过程；读 `storyboard.md`、`film.js`，C 还要读 `layout.js`。再按需读 `engine/vk.js` 和 `engine/vk-kit.js` 的相关实现。

沿用全局素材研究方法：粗时间覆盖全段，关键运动用连续序列加密；记录动作的准备、加速、接触/变化、结果、停留，以及镜头和字幕的先后。检查中间帧，不能只比封面或首尾。借鉴作者的机制表达和动作语言，新选题另写事实、脚本和画面；不照搬被排除授权的参考片字幕/场景。

## 可搬移的制作入口

用实际 Skill 绝对路径运行：

```text
python <skill>/scripts/new_vibe_film.py --output <project>/sample --world C --title "用户选题"
```

默认20秒，复制引擎、八个字体及许可证到作品目录。目标必须不存在，不覆盖用户文件。输出为明确标记的制作骨架：必须编写 `film.js` 中的用户场景与字幕，不能把骨架交给用户当样片。`--world B` 为寓言；`--duration` 只调整骨架时长，不压缩现有故事。

`--example` 仅复制选定世界的原作者参考工程用于研究，保持原始约33秒时长和署名。生成后可移动整个目录，不依赖 Skill 绝对路径、`/engine/` 特殊挂载或网络字体。不要把共享目录里的参考工程直接改成用户作品。

可用 `--audio <本地音频>` 复制音轨并绑定播放器，或把混好的音轨放入工程后在 `config.js` 设置 `audio` 相对路径。它不是自动混音器；旁白、BGM、动作声先按时间混合成一条音轨，用户要求的 BGM 优先。无音轨时播放器明确显示“无音轨”。

### 引擎关键契约

- `VK.film({dur, fps:60, theme:'night'|'flat', meta:{title}, draw(fr,t){...}})`；每帧只由时间 t 决定。禁止累计上帧位置，随机运动使用引擎的种子函数。
- `VK.seg(t,a,b)`、`ss(t,a,b)`、`lerp(a,b,k)` 组织局部时间；`fr.g` / `fr.layer` 分组变换；`fr.x` 是 Canvas 2D context。参数细节看源码，不猜 API。
- `VKit.subs(fr,t,[{a,b,zh,en?}],theme)` 绘字幕。`fr.look.under(ctx,t)` 可画不受辉光影响的实体；辉光强度服务材质，不把细胞/角色画成泛光团。
- 上游内部为1920×1080；其他画幅需要真正重排构图与引擎坐标，不能只改 CSS 拉伸。
- 本地播放器等待全部字体就绪，以 `seek(t)` 控制播放、暂停、拖动、重播与可选音轨；不要启用上游 `?play` 私有循环。
- 原作者参考默认30fps，骨架显式60fps；HTML播放顺畅不等于已经导出原生60fps MP4。
- `fr.sfx` 仅登记音效事件，不会在浏览器直接发声。可选 `tools/audio.py` 依赖 NumPy/SciPy，`--wav-only` 从项目 `audio/events.json` 合成 `audio/score.wav`。不要默认安装或运行；需要声音合成时才使用。事件按同刻同名去重，上游收集器会吞绘制异常，不能代替逐段视觉验收。
- 不并入上游 `render.py` 的 Chrome/Playwright 服务流程。预览与验收使用当前允许的内置浏览器；导出仅在用户要求时采用允许的本地渲染方式。

## 样片验收

检查首尾、全段粗采样、机制关键动作的连续密集采样，并实际播放连续过程。重点检查：动作是否证明了结论、对象身份是否稳定、字幕能否顺读、转场是否保持逻辑、字体是否完整、播放/暂停/拖动/重播及音画同步是否真实工作。静音预览不能算声音验收。把项目复制到 Skill 外的目录再次打开，确认不依赖原路径。
